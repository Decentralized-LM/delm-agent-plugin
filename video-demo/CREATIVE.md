# DeLM for Codex: product film

A 56-second product demo built around a concrete request and a real result. The viewer should understand how to try DeLM, see that it lives in Codex, and recognize why sharing unfinished work is useful.

## Direction

Warm white, dark ink, and DeLM blue. Geist for titles and the exact SF Mono font from the local Mac Terminal app for terminal text. SF Mono is cached locally for rendering and is not redistributed. After the title card, the opening reads “Build faster with DeLM.” on one line, with DeLM in blue at the same size. Three.js projects the terminal as one rigid surface, settling square before typing. The same window enlarges into Codex and contracts into the first worker. The title card carries the copy control. The next shot contains only the terminal and a naturally typed installer command. Functional text is front-facing when it needs to be read. Movement follows the cursor, the features, and the files. No decorative counters, percentage gauges, or invented performance claims.

Quiet, dry 18 ms digital ticks accompany typing. Mouse clicks and Enter are distinct. File movement is silent, with tiny ticks marking publication and import. The music is the original research-video recording, using its first 56.2 seconds at the approved gain and original tempo. There are no noise sweeps or brushing sounds. There is no voiceover, and the film must make sense muted.

## Accuracy

`npx delm-agent-plugin` is a user-approved future installer placeholder. It is not published yet. Installation, hook trust, and restarts are abridged; there is no hook review scene. Current installation uses the repository's source installer and still requires reviewing and trusting DeLM in `/hooks` and restarting Codex. The film reconstructs the terminal interface from Codex source snapshots. It is edited demonstration footage, not a recording of a newly timed DeLM run.

The collaboration sequence summarizes events from the completed Neon Rush session. Its feature canvases illustrate movement and the soundtrack; they are not recordings or measured progress. The game footage uses an unchanged copy of the retained output. The six-second result shot keeps the two agents' contributions visible as it closes the request, then returns to DeLM. The 25 passing checks refer to that real project. No measured DeLM-versus-baseline speed or quality comparison is presented.

The optional comparison belongs between collaboration and the result reveal. Add it only after matched real runs exist: the same request and model, authentic outputs, and measured timing. Use a fast match cut into the same task with and without DeLM, followed by the useful difference. Avoid shrinking two long terminal logs into unreadable columns. The current film contains no empty comparison slot or fake result.

## Production

Hyperframes renders the HTML, CSS, and GSAP timeline at 1920×1080, 60 fps. `src/timing.json` shares the edit's timing map with the sound mixer; `src/features.js` draws the feature illustrations. All fonts and footage are local. Headless browser capture preserves the actual game. FFmpeg prepares the sound and validates the MP4. Review includes selected frames, scene boundaries, reading time, and the exported video itself.
